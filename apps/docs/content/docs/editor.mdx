Each worktree has its own embedded IDE with a file explorer, extensions, terminals, and debugging.

## Embedded IDE

Choose **IDE** in the workspace's top bar or new-tab menu. The IDE opens that worktree's checkout using code-server, an open-source distribution of VS Code. The first launch downloads the editor runtime; later launches reuse it.

File search results, terminal file links, and **Open IDE** in a diff open the file in the same worktree's IDE. A line link moves to that line without reloading the IDE or closing other files. Browse and manage files in the IDE's Explorer.

Opening the IDE also reveals the worktree's **Changes** panel with **All changes** selected. This compares the branch with its base and includes committed changes. Use **Changes** in the IDE toolbar to return to that comparison. The IDE's own Source Control view lists uncommitted edits and requires workspace trust; it stays disabled in Restricted Mode until you choose to trust the folder.

Use the **Dark / Light** selector beside **Stop IDE** to change the editor's appearance. Each worktree remembers its choice, and new profiles start in dark mode. To choose another VS Code theme, open the IDE command palette and run **Preferences: Color Theme**.

You can turn the feature off in **Settings → General → Features → Embedded IDE**. This hides the entry points and prevents saved IDE panes from starting again. Open sessions remain available so you can save your work and stop them with **Stop IDE**.

The IDE includes the command palette, IntelliSense, code navigation, refactoring, source control, integrated terminals, and debugging. JavaScript and TypeScript language support and the JavaScript debugger are included. Node.js and any other tools your project uses must be installed on the workspace's host.

For Python, install these extensions from the IDE's Extensions view:

- **Python** (`ms-python.python`) for interpreter selection and Python commands.
- **Python Debugger** (`ms-python.debugpy`) for breakpoints and debugging.
- **BasedPyright** (`detachhead.basedpyright`) for completion, navigation, and type checking.

Select an installed Python interpreter and use **Run and Debug** to configure a launch. Extensions come from Open VSX, or you can install compatible VSIX files. Microsoft Marketplace-only extensions may be unavailable or incompatible.

Each workspace keeps its own extensions and settings. Switching tabs or workspaces preserves the running IDE and unsaved buffers. Closing an IDE pane closes its view; **Stop IDE** also ends that workspace's IDE terminals and debugging sessions. Save files before closing or stopping. Workspace deletion and host shutdown stop the runtime too.

The runtime supports macOS and Linux on Apple Silicon/ARM64 and x64. Native Windows hosts are not supported yet. For a remote workspace, extensions, terminals, and debug adapters run on the remote host and the desktop connects through Superset's authenticated forwarding.

Existing Files tabs migrate into the IDE. If the old editor still holds unsaved or conflicted changes, its recovery view stays open until you save or close it.

**⌘O** opens the workspace in an external IDE ([IDE Integration](/use-with-ide)).

## Save and Review External Changes

Use **Save** or **⌘S** to write your edits. If an agent or script changes the file while you have unsaved edits, the editor keeps your buffer and shows an external-change banner. Click **Compare** to review the disk and local versions side by side. Saving a conflicted file opens the same review.

- **Keep editing** preserves your unsaved edits without writing to disk.
- **Reload from disk** replaces your buffer with the disk version. It is unavailable if the file cannot be read.
- **Overwrite file** replaces the disk version with your edits.

The editor does not autosave or merge simultaneous edits.

## Markdown Links

Web links in Markdown previews follow **Settings → Links**. By default, Shift-click opens a new tab, Cmd/Ctrl-click opens a split browser pane, and Cmd/Ctrl+Shift-click opens the system browser. A plain click keeps you editing.

## Tabs, Splits, and Panes

The workspace shell supports tabs and split panes. Drop a pane onto the tab strip to create a new tab; mix terminals, the IDE, diffs, and browser panes in one layout. Moving an IDE pane keeps it connected to its original worktree.

### Branch changes inside the IDE

In the IDE Explorer, expand **Branch Changes** to see committed and local changes against the worktree's base branch. Selecting a file opens a native VS Code diff. Use the file's **Open File** action to edit it directly. Added, modified, renamed, and deleted files have status badges, including in the regular Explorer tree. The list refreshes after saving, returning to the IDE, and periodically while it is focused.

The comparison uses the same configured base branch as Superset's Changes sidebar and the merge base of that branch. It reads local Git refs without fetching. This read-only comparison works in Restricted Mode; debugging and other extensions still follow VS Code workspace trust.
